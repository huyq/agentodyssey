# AgentOdyssey TTCL 方案 v2：认知脚手架 + 程序性知识的选择性参数化

本文是 `TTCL_TEST_TIME_TRAINING_PLAN.md`（下称 v1）的修订版。修订依据：(a) 对官方规则原文的核实；(b) 对 v1 的理论分析（信息预算、信用分配、状态抽象、可验证性）；(c) harness 定义的扩展——harness 不只是事实账本，而是**prompt 级思维链约束 + 外部工具调用**的认知架构。

与 v1 的主要差异：

1. 规则边界按官方原文精确化，新增 prompt 知识禁令与设计红线；
2. "事实交 harness、策略进权重"从直觉升级为可操作的划分判据与正式定义；
3. harness 从被动存储/验证器升级为**认知脚手架**：固定推理协议 + 工具，两者相互作用；
4. 训练数据的选择从"事件类型清单"升级为**四道闸门的过滤级联**；
5. 训练目的修正：不是"内化后撤离脚手架"，而是"脚手架恒定在场下的行为默认化与工具使用熟练化"。

## 1. 比赛边界（按官方规则原文核实）

### 1.1 计分与协议

- 排名游戏：`remnant`、`mark`、`metropolis`；排名 = 三局主线 quest reward 的未加权均值（不做 per-game 归一化），supplementary 均值（side quest / exploration / craft / defeat）仅作 tie-breaker；论文须同时报告 per-game 数值。
- `max_steps = 500`；计分 backbone 仅 Qwen3-4B 或 Qwen3.5-4B（base / instruct / reasoning 变体均可）。
- 每游戏 standalone：在 AgentOdyssey 游戏中获得的 memory 和 learned state 必须在评测每个游戏前重置；无固定游戏顺序。
- 多次运行必须报告均值，禁止 best-of-N；官方不强制 seed 数；无提交期排行榜；top 方案会被核验代码与复现。

### 1.2 预训练禁令的精确语义

- 禁止在**任何** AgentOdyssey 生成的游戏上 pre-training——包括非排名游戏。
- "pre-training"是时间概念：评测 run **之内**、以当前局数据进行的在线训练（test-time training）不受限制，恰是比赛要测的能力。官方 SFT/RL baseline 均为局内在线训练，不违反规则。
- 外部数据训练明确允许：ALFWorld、ScienceWorld、WebShop 等，官方明示可用于 meta-learning。经外部训练得到的权重属于 agent 的固定先验（与 Qwen 预训练权重地位相同），不在 reset 范围内。
- **prompt 禁令**（v1 遗漏）：不得向 agent 的 prompt 注入超出默认动作空间的游戏知识。harness 的协议与提示必须可公开辩护为"通用决策程序"，不含针对排名游戏的窍门。

### 1.3 设计红线与卫生

- 不使用仓库自带 generator（`tools/generators/`）自造训练游戏——其产物属 AgentOdyssey-generated games，在禁止面内。
- 主要调参在非排名环境/代理任务上进行；排名游戏只做最少次数的确认性运行。超参与 prompt 的迭代本质是人工回路的信息泄漏，三个游戏 × 少量 seed 上调出的配置几乎必然过拟合。
- 规则模糊点：官方只要求"每个游戏评测前 reset"，未明示同一游戏多个 run 之间是否必须 reset。mean-not-best 使跨 run 学习自我惩罚，本方案按逐 run reset 处理；跨 run 学习曲线仅作为论文分析实验。

### 1.4 两环视角（备选项，默认不启用）

本方案主体是**纯内环**设计。外环（在 ALFWorld 等外部基准上 meta-train 先验：探索策略、价值头初始化、抽象器、KL 锚点）合规且被官方点名，是后续可启用的杠杆；其风险是外环任务分布与 AgentOdyssey 的结构距离决定迁移收益上限（负迁移风险）。启用与否不影响内环设计。

## 2. 核心划分：陈述性知识外存，程序性知识入参

### 2.1 失败诊断（官方论文实测）

- 官方 SFT baseline 将 observation-reasoning-action 全文参数化：实测 action diversity 坍缩、World Knowledge QA 训后**下降**（catastrophic forgetting）、reward 平台化。
- Long Context agent 在纠正性反馈**就在上下文里**时仍反复执行同一错误动作：**被动可用 ≠ 被使用**。

### 2.2 划分判据（替代"低维/高维"的直觉说法）

- **专名测试**：删掉所有实体名、地名、时间戳后仍是有意义的行为指导 → 策略；语义崩坏 → 事实，归外存。
- **可枚举性测试**：可穷举写下、需要时按索引查到的 → 外存；必须在**未见状态**上求值的函数 → 参数。

### 2.3 正式定义

> 进入权重的训练数据 = 当前局 action-outcome 联合分布在 harness 状态抽象下的**充分统计量**，不含实体 token。

单个事件只能产生事实；多个事件的聚合（计数、比较、排序）才产生策略。harness 负责分组、计数、验证，权重吸收条件分布。

### 2.4 为什么是权重而不是 prompt（参数化的不可替代性）

- **可靠性地板**：prompt 空间的信息要影响行为，必须通过"想起要查 → 查到 → 注意 → 服从"的一串可错环节；失败抑制、受阻切换这类倾向恰恰要在最困惑、最不可靠的时刻起作用，其唯一载体是权重。
- **工具使用质量的上游是内化图式**：知道"查什么、何时查"本身需要已内化的领域结构；内化不是工具使用的替代，而是它变好的机制。
- **瞬时内容不参数化**：背包、位置、HP 是快变量，权重是慢变量，参数化瞬时状态是范畴错误——这是工具部分**永存**的信息论理由，而非偏好。

### 2.5 训练目的的精确陈述

> 在脚手架**恒定在场**的条件下（训练与评测同分布：π(action | observation, scaffold context)），把脚手架催生的、经结果验证的行为变成默认行为，并提升脚手架使用的熟练度与经济性。工具因内容瞬时而永存；纪律因可内化而训练；内化是机制，不是撤离。

推论：永远只训练含完整脚手架上下文的轨迹；永远不在无脚手架配置下评估——train/test 一致是纪律而非假设。

## 3. Harness：认知脚手架

harness = **工具**（外部存储与校验，永久在场）+ **脚手架**（prompt 级推理协议，其纪律被内化）。两者持续相互作用。

### 3.1 工具部分

复用并扩展现有 `harness/` 模块：

- `StateLedger`：事实（含置信度/证据步/最近验证步）、位置与邻接、背包与装备、vitals、失败记录、进度；
- `EventLog`：事件流与 outcome 分类（success / progress / no_effect / invalid / death）、reward delta；
- `ActionValidityMask` 与检索接口。

### 3.2 脚手架部分：固定推理协议

每步决策强制执行游戏无关的五阶段协议：

1. **状态评估**：ledger summary 直接注入，模型不复述事实；
2. **强制记忆查询**：模型以结构化形式发起查询（当前阻塞？同类失败记录？相关 skill？），harness 执行并返回——把"被动注入"变为"主动索求"，查询行为本身成为可训练对象；
3. **候选枚举**：在 valid action mask 上进行，合法性是推理的属性而非事后补救；
4. **前置条件检查**：模型对候选可行性做 claim，harness 对 ledger 可查项判定真伪——不一致即检查点级负样本（process supervision）；
5. **决策输出**。

协议结构是手工归纳偏置，**协议即学习的上限**；因此协议只含通用决策分解，不含任何游戏特定内容（prompt 禁令的合规要求）。

### 3.3 两部分的相互作用

- **熟悉度自适应审议**：ledger 维护每个抽象条件簇的经验计数与结果稳定性。routine 状态（高计数、估计稳定）走快通道，跳过阶段 2–4；novel/受阻状态走完整协议。
- **fast-path 占比**是内化程度与 token 经济性的指标（不是撤离进度——脚手架一步都不撤）。可证伪预测：fast-path 占比上升时性能不降，才说明内化真实发生。
- **skill = 缓存的子协议**：被重复验证的推理+动作序列降级为快通道原生执行；"学会技能" = 该子协议不再需要逐段支撑。

### 3.4 失败模式诊断路由

harness 统计（invalid rate、重复动作、候选-选择对照）诊断当前失败类型，选择**侵入性最小**的学习目标：

| 失败模式 | 诊断信号 | 学习目标 |
|---|---|---|
| 提不出正确动作（proposal） | 正确动作不在候选集中 | actor 正样本（抽象条件 → 动作类型） |
| 提得出选不中（selection） | 正确动作在候选中但排低 | value/reranker 排序对 |
| 知错不改（suppression） | 同条件同动作反复失败 | 失败统计的对比压制 |
| 前置判断失真（calibration） | claim 与 ledger 判定矛盾 | 检查点级纠正 |

## 4. 数据过滤：四道闸门

原则：**LLM 只产生候选，harness 的确定性逻辑执行全部筛选**。模型是假设生成器，harness 是检验器。

### 4.1 级联

1. **认识论门槛（可信吗）**：只接受 (a) 环境信号的确定性函数（outcome、reward delta、invalid、mask 判定、ledger 对 claim 的真伪判定），或 (b) 协议内通过检查点验证/结果背书的片段。拒收：原始 observation 文本、协议外的模型自由文本（reflection、未验证假设挂"待验证"，攒够环境证据后方可回流）。
2. **参数化资格（该进权重吗）**：专名测试 + 复发测试。复发在**抽象条件簇**层面度量：簇计数 ≥ k；高量级结局（死亡、主线推进）可降低计数要求（期望收益 ≈ 复发概率 × 结局量级）。一次性事件流向 ledger——一次性成功是新闻，重复出现的模式才是政策。
3. **分歧度门槛（有信息量吗）**：只训练策略与证据不一致处——修正对（同条件下 A 失败 k 次后 B 成功）、校准错（claim 被 ledger 证伪）、排序错（验证为优的动作被排低）。当前策略已掌握的行为至多进 replay 保底，不驱动更新（否则只施加熵坍缩压力）。
4. **路由（怎么用）**：按 §3.4 的失败模式决定 loss 类型与目标模块。

### 4.2 组批规则

- **负样本永不单独入训**：每个"别做 X"必须与同条件簇内验证过的修正动作配对，否则概率质量只压不引，导致输出退化。
- **条件簇去重与限流**：单簇在一次更新中有份额上限，防止一个反复失败的模式主导梯度（其本身即坍缩通道）。
- **陈旧性区分**：affordance 统计（环境的性质）不衰减；价值/排序估计（当时策略的性质）按 recency 衰减。
- **样本权重 = 结局量级 × 分歧度**；replay 混入少量旧样本维持稳定。

### 4.3 两个时间尺度与更新级闸门

- **逐事件在线初筛**（便宜）：来源、验证状态、专名测试、归档入簇；
- **触发时组批**（需全局视图）：复发计数、分歧打分、配对、去重限流、陈旧衰减。更新触发 = 高量级事件即时触发，或积累 n 条分歧后触发（事件触发 + 积累兜底）；
- **更新级闸门**：每次更新后用留存验证集快速自检（已验证排序对是否保持、采样决策是否退化、KL 是否超预算），不过则回滚。过滤器不只筛数据，也筛更新——500 步内一次坏更新的代价高于十次错过的更新。

### 4.4 存活量预期

全部闸门作用后，500 步事件的预期存活量为：几十条修正对与校准错、个位数 option、少量排序对，驱动个位数到十几次更新。两个可证伪诊断：

- 放行数百条 → 某道闸门泄漏（最可能是分歧度或限流）；
- **整局零存活是合法答案**：抽象条件复发率撑不起参数化时，检索即正解，不硬训。

### 4.5 闸门—疾病对照

| 闸门 | 防什么 |
|---|---|
| 认识论门槛 | 自蒸馏 / 合理化（官方 baseline 的实测死法） |
| 专名测试 | 事实参数化 |
| 复发测试 | 预算烧在不可复用的经验上 |
| 分歧度门槛 | 自我强化导致的熵坍缩 |
| 负样本配对 | 纯负样本导致的输出退化 |
| 簇限流 | 单一失败模式主导梯度 |
| 陈旧衰减 | 旧策略估值污染新策略 |
| 更新后自检 | 不可逆的坏更新 |

## 5. 训练目标与更新机制

- **loss mask 跟随协议的可验证性结构**：检查点输出与最终决策计入 loss（按 §4.2 加权），自由过渡文本不进 loss——既保留"训练思维链"的实质，又堵住 rationale 不可验证的合理化通道。
- **训练分布恒定含完整脚手架上下文**（见 §2.5）。
- **KL 锚定 base + 小步低秩 + replay**；更新为事件触发与积累兜底（见 §4.3）。
- **时间感知**：剩余步数进入状态摘要。有限时域下最优策略非平稳——同一抽象条件在第 50 步与第 450 步的正确动作可以不同；价值估计应为 V(s, t)。
- **目标对齐**：训练信号的标量化与官方词典序目标同构——主线进度的因果贡献为主；supplementary 事件作为探索多样性代理，而非与主线等权的正样本（500 步机会成本是硬约束）。
- **信用分配**：reward_delta 归属当步不构成信用分配（造钥匙得 0 分、开门得全分）。延迟效应由价值估计/reranker 处理；轨迹/lesson 加权应理解为 advantage 加权的特例而非启发式。候选来源优先 mask/valid_actions（免采样、保合法），模型采样仅作补充。
- **探索是结构不是学习目标**：单局内"学会探索"在样本复杂度上不可行；新颖性/好奇心以注入式偏置（计数奖励、重复惩罚、候选扰动）实现。

## 6. 评估设计

### 6.1 排名协议

逐 run reset、iid 运行、报告均值；`challenge_eval.py` 聚合。

### 6.2 核心零假设

> **参数化 TTT 不优于"同等信息的非参数化 agent"（ledger + lesson/轨迹检索，权重不动）。**

这是首要对照：与 No Memory 对比测到的是"信息有无"，与同等信息检索基线对比测到的才是"学习有无"。参数化必须在这个对照下自证价值。

### 6.3 测量"学习"本身，而非只测结果

- 局内学习曲线：后半局 vs 前半局的斜率，与非学习基线的斜率差；
- fast-path 占比随步数的轨迹（内化与成本指标）；
- World Knowledge QA / Episodic Memory QA 前后差（区分事实记忆与经验记忆，复用 `tools/generate_*_qa.py`）；
- action diversity 轨迹（坍缩检测，对齐官方论文的观测）；
- **去脚手架 ablation**（仅 dev 阶段）：去掉强制提示后权重单独表现相对 base 的提升 = 内化真实发生的直接证据。排名 run 永远全 harness。

### 6.4 统计纪律

- seed 数由期望效应量与单局方差反推，而非统一"至少三次"；报告 mean±std 与分游戏数值；
- 跨方法使用配对 seed；
- 消融清单：raw trajectory SFT vs 四闸门过滤、事实入 prompt vs ledger、每步更新 vs 触发更新、无 KL vs KL、actor LoRA vs frozen+reranker、无 skill vs skill、有无检索对照。

## 7. 与官方 baseline 的关系

官方 SFT/RL baseline 均为纯内环局内训练，本方案与之同预算对比，胜负归因于学习算法而非信息优势。本方案的增量来源：认知脚手架（协议 + 过程监督 + 诊断路由）与数据过滤（四闸门）——其靶点正是官方论文已实测的基线失败模式（坍缩、遗忘、知错不改）。

## 8. 开放问题与风险登记

1. **状态抽象是全部泛化的上限**：lesson/统计的有效性不超过抽象与 bisimulation 的对齐程度；抽象当前为手工固定，与"经验推进会改变相关特征"存在张力。
2. **协议结构是学习上限**：错误的手工阶段结构会被内化；协议必须保持通用且可公开辩护（prompt 禁令）。
3. **CoT 训练的自蒸馏风险**高于动作级训练；loss mask 纪律是唯一防线，放松即退回 baseline 的合理化陷阱。
4. **更新回滚的有效性**依赖留存验证集的代表性；小样本下自检可能漏检缓慢退化。
5. **外环是否启用**：合规且有官方背书，默认不启用；若启用，KL 锚点改为 meta-prior，需评估负迁移。
6. **同一游戏跨 run 学习的规则模糊点**：本方案按逐 run reset 处理（见 §1.3）。
